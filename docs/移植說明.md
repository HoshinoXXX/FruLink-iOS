# FruLink Android 1.5.12 → iOS 移植說明

## 一、原版是什麼

FruLink 是一個 **WebView 殼應用**：Android 側只負責加載
`https://kei.tendouaris.com/upload/frulink/index.html?v=4`，全部業務邏輯在網頁端。
因此 iOS 移植的核心是：**用等效的 WebView 加載同一網頁 + 復刻原版的 JS 橋與更新機制**。

## 二、功能對照表（Android → iOS）

| Android 原版（反編譯自 dex） | iOS 移植實現 |
|---|---|
| `WebView.loadUrl(HOME_URL)` | UIWebView（iOS 5–7）/ WKWebView（iOS 8+）加載同一 URL |
| `setJavaScriptEnabled(true)` | UIWebView/WKWebView 默認支持 JS |
| `setDomStorageEnabled(true)` | 默認支持 |
| `setUseWideViewPort + setLoadWithOverviewMode`（按屏寬縮放） | `scalesPageToFit = YES`（**屏幕拉伸效果**） |
| `setSupportZoom(false)` | 默認禁用手勢縮放（WK 不配置捏合縮放） |
| `addJavascriptInterface(new JsBridge, "FruLinkApp")` | 注入同名 `window.FruLinkApp` 對象（WK 在文檔開始時注入，時機一致） |
| `JsBridge.checkUpdate()` | `frulink://checkUpdate` → 原生檢查更新（manual=YES） |
| `JsBridge.exitApp()` | `frulink://exitApp` → `exit(0)`（越獄版直接退出） |
| `JsBridge.getVersionName()` | 注入時直接返回 `CFBundleShortVersionString`（1.5.12） |
| `JsBridge.kb()` | `frulink://kb` → JS 聚焦頁面第一個輸入框 |
| `configChanges` 含 orientation/screenSize（旋轉自適應） | 全方向旋轉 + autoresizingMask 重鋪滿 |
| `checkUpdate(manual)`：GET `version.json?t=<毫秒>`，8 秒超時 | 同一 URL/超時，`NSURLConnection` |
| `version.json` 字段：versionCode/versionName/apk/notes | 同一 JSON 解析，`versionCode` 對比 `CFBundleVersion`(18) |
| 更新對話框（標題/正文/「立即更新」/「以後再說」） | 文案逐字一致（UIAlertView / UIAlertController） |
| `downloadAndInstall(apk)`：下載到 `cache/updates/`，進度 250ms 刷新 | 下載到 `Caches/updates/`，進度提示一致；>10000 字節校驗一致 |
| `installApk()` | 越獄設備 + IPA + appinst → 自動安裝；否則提示文件路徑 |
| `shouldInterceptRequest`：Live2D 資源走本地 assets | `Live2DURLProtocol`：優先讀 app bundle `live2d/` 目錄（含 CORS 頭），否則網絡 |
| 主頁加載失敗 → 離線提示頁 | 同一 HTML 文案（dex 字符串 #17 逐字復刻） |
| 啟動 1.5 秒後自動檢查更新 | 同樣 1.5 秒 `dispatch_after` |
| 背景色：加載中 #6893D9 / 完成 #F7FAFF | 完全一致（啟動圖也用 #6893D9，無縫銜接） |

## 三、iOS 兼容策略

- **iOS 5.0–7.x**：`UIWebView`（iOS 2 起存在），委託方式攔截 `frulink://` 協議；
  橋在 `webViewDidFinishLoad` 注入（這幾代系統無法更早注入，屬平台限制）。
- **iOS 8.0+**：`WKWebView` + `WKUserScript` 在**文檔開始時**注入橋，
  與 Android `addJavascriptInterface` 的時機完全一致，網頁啟動即能調用。
- 代碼用 `#if __IPHONE_OS_VERSION_MAX_ALLOWED` 做編譯期分支，
  舊 SDK（Xcode 6/7）與新 SDK 都能編譯。

## 四、關於「免簽名」的技術說明

iOS 內核要求所有可執行文件帶有效代碼簽名。所謂「免簽」指**不使用 Apple 開發者證書**，
但仍需要兩樣東西（構建腳本已自動處理）：

1. **假簽名（ldid -S）**：給二進制加一個自簽偽簽名，越獄設備的內核（有越獄補丁）接受它；
2. **AppSync Unified**（設備端插件）：安裝時繞過簽名校驗。

所以：*沒有 Apple 賬號、沒有證書、沒有設備 UDID 註冊*，照樣能裝能跑——這就是「越獄版軟件」。

## 五、更新機制在 iOS 上的注意事項

原版服務端 `version.json` 的 `apk` 字段返回的是 **APK 鏈接**。iOS 端邏輯保持不變，
但安裝行為按文件類型分流：

| 場景 | 行為 |
|---|---|
| 越獄設備 + 鏈接是 `.ipa` + 已裝 `appinst` | 自動安裝新版本 |
| 鏈接是 `.ipa`（無 appinst / 非越獄） | 下載完成，提示文件路徑（可用 Filza 安裝） |
| 鏈接是 `.apk` | 下載完成並提示「APK 無法在 iOS 安裝」，建議服務端對 iOS 返回 IPA 鏈接 |

> 服務端（或網頁端）可通過 User-Agent 判斷 iOS，在 `apk` 字段返回 IPA 下載鏈接即可實現全自動更新。

## 六、已知平台差異

1. **文件選擇器**：iOS 6+ 的 UIWebView / iOS 8+ 的 WKWebView 原生支持
   `<input type="file">`，無需代碼；iOS 5 不支持（平台限制，與原版 Android 5.0+ 行為類似範圍）。
2. **kb()（軟鍵盤）**：iOS 不允許原生代碼強制彈鍵盤；實現為聚焦第一個輸入框，
   由系統在輸入框聚焦時彈出鍵盤（Android 的 `showSoftInput` 無 iOS 等價物）。
3. **退出**：`exitApp()` 對應 Android `finishAndRemoveTask()`，iOS 用 `exit(0)`（越獄版可接受）。
4. **Live2D 覆蓋**：原版 APK 的 assets 目錄為空，本地覆蓋為預留能力；
   需要時把資源放進 app bundle 的 `live2d/` 目錄即生效（注意 WKWebView 不走
   NSURLProtocol，此特性僅 UIWebView 路徑生效）。

## 七、構建矩陣

| 目標設備 | 腳本 | 環境 | 架構 / 最低系統 |
|---|---|---|---|
| 現代越獄設備（iOS 12+） | `./build-ipa.sh` | macOS + Xcode 14/15/16 | arm64 / 12.0 |
| 較新 arm64 設備（iOS 8–11） | `./build-ipa.sh iphoneos arm64 8.0` | 同上 | arm64 / 8.0 |
| 老 32 位設備（iOS 5–10） | `./build-legacy-armv7.sh` | macOS + Xcode 6/7 + 舊 SDK | armv7/armv7s / 5.0 |
| 越獄插件方式（.deb） | `make package`（Theos） | macOS/Linux + Theos | 見 Makefile |

## 八、安裝到越獄設備

1. 設備越獄（unc0ver / checkra1n / palera1n / Dopamine 等，iOS 5 老設備用 evasi0n7 等老工具）；
2. 安裝 **AppSync Unified**（Cydia/Sileo 源：`cydia.akemi.ai`）；
3. 把 `FruLink_1.5.12_jailbreak.ipa` 傳到設備，Filza 打開 → 安裝；
   或電腦端用愛思助手 / sideloadly 導入。
